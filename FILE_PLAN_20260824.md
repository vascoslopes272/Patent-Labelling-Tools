## 4. ⚠ Found while reading `CHANGELIST_v3.md` — 2 open items that hit Batch_04

`CHANGELIST_v3.md` is 7/11 done. **M-1 and M-2 are still open**, and they are the same class
of bug as the TP→TR one fixed today — the Python predictor offering a value the wizard retired:

| | file | still there |
|---|---|---|
| M-1 | `src/cross_modal.py:681` | `("VarInc", "aircraft with a variable incidence wing…")` in the FUS_KIN prompt list |
| M-2 | `src/vlm_extractor.py:86` | `"variable": "VarInc" … "incidence": "VarInc"` synonym map |
| M-2 | `src/vlm_extractor.py:358` | JSON schema string `"fusKin": one of ["Fixed","VarInc","TiltBody"]` |
| M-3 | `src/excel_schema.py` | `_M1_FUS_KIN_DEFS` — **done**, no `VarInc` left |

**The drift guard cannot catch M-1/M-2.** It checks `_M1_FUS_KIN_DEFS` (excel_schema) against
the wizard's `FUS_KIN`, and the wizard deliberately still *contains* `VarInc`/`Variable` so old
records load. So `model ⊆ wizard` holds, the test goes green, and `cross_modal`/`vlm_extractor`
are not covered by it at all.

Consequence for **Batch_04**: SigLIP/SBERT would pre-label patents `VarInc`, a value retired as
a reviewer choice — every one then becomes a `bodyMotion` worklist decision in 02a. Worth
fixing in the same pass as TP→TR, before running 01a.
