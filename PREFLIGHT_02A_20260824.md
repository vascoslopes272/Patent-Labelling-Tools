## Issues, worst first

### 1. Section 5c decisions do NOT reach the same session's Section 6 export

`Section 5c` (cell 34) reads `reviewed_patents_<batch>.xlsx` from disk into `tgt`,
applies your decisions, and writes the file back. **It never assigns to `df`.**
Section 5b and Section 6 both run off `df`, which still holds the pre-decision values.
Nothing in the notebook says to re-run.

So: sit through 80 decisions → run 5c → run Section 6 → the export silently contains
**none** of them.

*Workflow:* after 5c, re-run from Section 3 (which reloads `03c`) before Section 6.
Or add `df = pd.read_excel(target_xlsx, sheet_name="Review")` at the end of 5c and
re-run Section 4's pipeline.

### 2. The `t1Reason` panel is blank on 33 of 34 items

`t1Reason` is the only question that looks at *disapproved* patents, and the wizard's
`recordToRows()` truncates a disapproved record to verdict + reason — so `title`,
`abstract` and `description_of_drawings` are absent. The right-hand panel shows "—"
on every one of them, while the question's own help text says *"Check the drawings
description on the right before deciding."*

Six items have **no figure and no text at all**:

- Batch_01 `US2008243313A1`
- Batch_02 `FR2830237A1`
- Batch_05 `CN108706104A`, `FR3104333A1`, `US2022355944A1`, `JP2026505730A`

The metadata exists — `ml_predict_labels_<batch>.xlsx` under
`data/00b2_crops_and_01a_MACHINE_feed/<batch>/` has `title`/`abstract`/
`description_of_drawings` for all of them. A fallback lookup in
`build_worklist()`'s `meta()` would fill every panel.

### 3. `02a_legacy` deletes `boomN_wingSpan` from 162 boom groups without filling `wingRel`

`boom<N>_wingSpan` was retired in the wizard on 2026-08-06 and replaced by
`boom<N>_wingRel` (2026-08-07), which the wizard exports **blank** for any group
labelled before that date. Current state of wing-attached boom groups:

| batch | wing-attached groups | `wingRel` filled | blank | `wingSpan` rows |
|---|---|---|---|---|
| Batch_01 | 105 | 0 | 105 | 107 |
| Batch_02 | 95 | 80 | 15 | 11 |
| Batch_03 | 93 | 93 | 0 | 0 |
| Batch_05 | 57 | 0 | 57 | 37 |

Running `02a_legacy` on Batch_01/05 drops the 144 surviving `wingSpan` rows
(Half/Full) and leaves `wingRel` empty, so those groups end up with **no**
wing-relative position, and no worklist question asks for one. Recoverable — Section 9
writes a `PRE_CONFORM_<ts>` backup — but decide whether to harvest wingSpan→wingRel
first.

### 4. One APPROVED image path is dead and 02a will not tell you

02a validates *blank* `Image_Path` cells but never checks that a **non-blank** one
still exists. Eight are dead across the corpus; seven are on disapproved blocks
(harmless, dropped at export). This one is not:


The file is gone from `00b2_figure_crops/Batch_02/WO2010132901A1_43085383/`; the
folder now holds `..._img9_crop_1_F5.png` (also approved, and marked main), so this
looks like a re-crop whose old block was left behind. It will pass the approved-only
filter and reach 02b as a broken path.
